Examiner Demo Guide

These steps show the main behavior implemented in the backend.

1

Reserve a pair

Use user1 and click Buy & Hold. Stock decreases and the user enters HELD state with a 5-minute countdown.

2

Complete payment

Click Pay while the hold is active. The user becomes PURCHASED and the purchase count increases.

3

Test duplicate payment

Use Fake Payment and enable duplicate notification. The backend handles the second payment safely.

4

Test waiting queue

When stock is 0, use another user and click Join Waiting Queue. Their FIFO queue position appears above.

5

Test purchase limit

A user can complete two purchases. A third purchase is rejected because the maximum is 2.

6

Explain concurrency

Redis performs the stock reservation atomically, preventing multiple simultaneous requests from selling more than the available inventory.

Implementation Overview

The UI is only a demonstration layer. The important logic runs in the Node.js + Redis backend.
